# 性能

- 更新：2026-11-02
- 预算见[路线图](../plan/roadmap.md)「性能预算」：1080p 稳定 60 帧，GPU 10 毫秒以内；draw call 500 以内，三角形 200 万以内，阴影和法线遍都算在内

## 测法

```bash
pnpm perf spots                # 跑一个命令
pnpm perf startup enter leak   # 几个命令按顺序跑；all = startup spots enter leak stutter
pnpm perf --help               # 全部命令和选项
```

脚本在 `scripts/perf/`，从主仓库搬来，改用这里的调试接口（`__game.level`、`__game.debug.invincible`）。它在 5291 端口起一份当前代码的开发服务器，测完关掉（`--url` 改量别的地址），用本机 Chrome 无界面打开（ANGLE Metal，默认关垂直同步，`--vsync` 锁 60 帧），视口 1600 × 900（`--width`、`--height`）、像素比 1（`--scale`），量的是开发版。结果写在系统临时目录的 `isles-cartoon-perf/<时间>/`：每个命令一份 `<命令>.json`（全部原始数据）和 `<命令>.md`（表格），再加一份 `summary.md`；`--out` 改目录，`--label` 给这次测量起名。要用关卡的命令默认只跑 1-1，`--levels` 可以加别的关；1-2~1-5 还是俯视版的布局，能进能打，数字不代表第一人称版。

| 命令 | 量什么 | 怎么量 | 选项（括号里是默认值） |
|---|---|---|---|
| `spots` | 重点位置的 draw call、三角形、帧时间和主线程的 p50 / p95 | 到 `spots.json` 里的每个位置站定（重开本关、主角无敌、传送过去、不动），热身后量几秒钟；draw call 和三角形是一帧里主遍、法线遍、阴影遍的合计 | `--spots`、`--levels` 只量一部分；`--seconds`（4）、`--warmup`（1） |
| `startup` | 从导航起到整备界面出现、可以操作（`window.__game` 就绪）、模型下载完、解码 / 转码完、第一次着色器链接和贴图上传、当前关（1-1）准备好的时间；长任务；下载个数和大小；KTX2 转码张数和耗时；整备界面期间每帧的间隔；启动后的 JS 堆、显存贴图和缓冲、`renderInfo()`、已加载模型、渲染进程和 GPU 进程内存；一出整备界面就点「出发」要等多久进关 | 每次新开浏览器上下文冷启动一遍、刷新热启动一遍，再新开一个上下文在整备界面一出现就点出发，几次取中位数。「当前关准备好」是最后一次着色器链接或贴图上传的时刻，之后 `--quiet` 毫秒里没有 GL 资源操作、网络请求、解码和转码 | `--runs`（3）、`--quiet`（2000） |
| `enter` | 从整备界面调 `startLevel` 到 `screen === 'play'` 的时间；期间的下载、解码 / 转码、着色器链接、贴图上传；进关后第一帧（rAF 间隔 / 主线程）和前 30 帧里最长的一帧 | 同一页按 `--levels` 的顺序进 `--rounds` 轮，每次先回整备界面等 `--settle` 毫秒。整备界面在后台准备的是 1-1，第一轮的 1-1 记作「整备界面已在后台准备」；要量没准备过的关，在 `--levels` 里加上别的关（比如 `1-1,1-2`） | `--levels`（1-1）、`--rounds`（2）、`--settle`（1500） |
| `leak` | 每次进关后的 geometries / textures / programs、JS 堆、解码贴图、显存贴图（其中压缩）和缓冲、渲染进程和 GPU 进程内存 | 从整备界面按 `--levels` 循环进关 `--rounds` 轮，再在 `--level` 同关重开 `--restarts` 次；每次进关后开自动驾驶（完美、无敌）实打 `--play` 秒，强制 GC 后记录；表下比较第一轮和最后一轮、开局和最后一次重开 | `--levels`（1-1）、`--rounds`（3）、`--level`（1-1）、`--restarts`（10）、`--play`（3） |
| `stutter` | 超过 16.7 / 33 ms 的帧、最长帧、帧时间 p50 / p99、着色器链接和贴图上传的次数和耗时、通关那一帧 | 每关新开一页，自动驾驶（完美、无敌）实时从进关打到通关，同一页重开再打，逐帧记录；途中每秒调一次 `skipDialogue()`；统计到通关前一帧，通关那一帧（尾声对话、结算）单独列；超过 16.7 ms 的帧每遍列最长的 10 个 | `--levels`（1-1）、`--runs`（每关打几遍，2）、`--max-minutes`（每遍最多跑几分钟，10）、`--capacity`（每遍最多记几帧，600000） |

2026-11-02 在 1-1 上各跑了一次（Apple M4 Pro，Chrome 156，不锁帧；同时有别的代理在跑，load average 10~17，帧时间偏大）：

- `startup`（3 次中位数）：冷启动 360 ms 出整备界面，760 ms 模型下完，944 ms 1-1 准备好；刷新后 235 / 397 / 598 ms。下载 65 个文件 27.6 MB，KTX2 转码 82 张，链接 32 个程序，长任务 3 个共 357 ms（最长 129 ms）。启动后 JS 堆 29.6 MB、渲染进程 272 MB，显存贴图和 geometries 都是 0：整备界面盖住画面时不画 3D，贴图要到进关后才上传。一出整备界面就点出发，等 710 ms 进关
- `enter`：1-1 第一次进 10 ms（整备界面已在后台准备好），回来再进 5 ms；但第一次进关后的第一帧要 300~590 ms（三次量到 588、428、308 ms，主线程占满），回来再进的第一帧 11 ms。整备界面不画 3D，只对场景做了 `compileAsync`，贴图上传（394 次，其中压缩贴图 375 次）和 50 个程序的链接都压在这一帧：阴影深度、法线遍、手臂和枪的材质、自定义着色器，还有地形、水、麦秆、木头、石头这些关卡材质又编了一套变体。加上没准备过的 1-2（`--levels 1-1,1-2`）：第一次进 164 ms（下载 12 个文件 16.2 MB、转码 16 张），第一帧 36 ms
- `leak`：第一次进 1-1 后 geometries / textures / programs 是 268 / 77 / 83，进 3 轮不变；重开 10 次只各多 1（第 5、6 次重开时出现，之后不再涨），JS 堆 34.0 → 35.3 MB，渲染进程 277 → 285 MB，显存贴图 95 MB（其中压缩 17 MB），没有泄漏
- `stutter`：冷跑 82 秒通关，11392 帧，帧时间 p50 / p99 7.1 / 19.3 ms，超过 16.7 ms 的 298 帧、超过 33 ms 的 16 帧，链接 60 次、上传 446 次；最长的 428 ms 就是进关后第一帧，另有 5 帧 113~293 ms（其中 3 帧有新链接的程序）。同一页重开再打 92 秒，16181 帧，没有链接，上传 62 次，最长 72 ms，超过 33 ms 的 9 帧

注意：

- 页面初始化脚本是 `scripts/perf/probe.js`：屏蔽 Vite 的热更新 websocket（不然别处改文件会整页刷新、打断测量，别的代理在同一个工作区改代码时也能量）；记 rAF 间隔和同一帧里 rAF 回调的总耗时（主线程）；包住 WebGL 的 `linkProgram`、等编译结果的 `getProgramParameter` 等记着色器链接，包住 `texImage2D` / `texSubImage2D` / `texStorage2D` / `compressedTexImage2D` / `generateMipmap` 等记贴图上传和显存贴图（压缩格式按块算），`bufferData` 记显存缓冲；包住 `createImageBitmap` 和 KTX2 转码 worker 记解码和转码；通过 three 的开发者工具钩子拿到渲染器，每次 `render` 后读 `renderer.info`（`autoReset` 关着，读到的是这一帧到这时为止所有遍的合计）
- 帧时间和主线程受机器负载影响很大，要比改前改后就在同样的负载下先后跑两边；draw call、三角形、链接和上传次数、资源数和内存跟负载无关，可以直接比
- 进程内存用 macOS 的 `footprint`（渲染进程取 CPU 时间最多的那个页面进程），其他平台这一项空着
- 一次只跑一个 `pnpm perf`（默认用 5291 端口，`--port` 可以改）；端口和 `pnpm e2e`（5290）、`pnpm shots`（5292）错开，能同时起，但同时跑会抢 CPU，帧时间就不准了
- 主仓库另有 `drawcalls`（draw call 按来源拆）、`next`（从结算界面进下一关）、`quality`（画质档位）、`scan`（每个区域量一遍）、`spikes`（长帧对到 CPU profile），还没搬。`spots` 的 GPU 计时也没搬：墨线管线自己用 timer query 量每一遍（`__game.styleInfo()`），同一时刻只能有一个 timer query 在量

内置浏览器面板隐藏时 requestAnimationFrame 几乎不跑，在那里读 `renderInfo()` 不准，性能数字一律用这个脚本量。
