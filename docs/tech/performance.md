# 性能

- 更新：2026-11-02
- 预算见[路线图](../plan/roadmap.md)「性能预算」：1080p 稳定 60 帧，GPU 10 毫秒以内；draw call 500 以内，三角形 200 万以内，阴影和法线遍都算在内

## 测法

```bash
pnpm perf spots
```

脚本在 `scripts/perf/`：在 5291 端口起一份开发服务器，用本机 Chrome 无界面打开，到 `spots.json` 里的每个位置站定（主角无敌、不动），量几秒钟的帧间隔、游戏每帧回调的耗时，以及每帧的 draw call 和三角形数（`__game.renderInfo()`，主遍、法线遍、阴影遍合计）。结果写在系统临时目录的 `isles-cartoon-perf/<时间>/`，`--label` 给这次测量起名，`--spots`、`--levels` 只量一部分，`--url` 量别的地址。

内置浏览器面板隐藏时 requestAnimationFrame 几乎不跑，在那里读 `renderInfo()` 不准，性能数字一律用这个脚本量。

主仓库 `scripts/perf` 里的启动、进关、泄漏、卡顿、长帧等命令要用到自动驾驶，等第一人称自动驾驶接上以后再搬。

## 1-1 的现状（2026-11-02，Apple M 系列 Mac，1600 × 900）

| 位置 | draw call | 三角形（万） | 帧时间 p50 / p95（ms） |
|---|---|---|---|
| 起点，看向北边 | 662 | 99.9 | 2.9 / 4.6 |
| 风车坡 | 855 | 178.1 | 3.8 / 7.2 |
| 晒谷场 | 749 | 157.3 | 3.9 / 5.2 |
| 晒谷场，回头看来路 | 611 | 126.6 | 3.2 / 4.6 |
| 田埂小路 | 549 | 128.3 | 3.1 / 5.6 |
| 收割场 Boss 战 | 509 | 116.6 | 2.6 / 4.0 |

帧时间离 16.7 毫秒还远，但 draw call 超了预算，主线程耗时和帧时间几乎一样，说明卡在 CPU 提交 draw call 上，配置差的机器会先在这里出问题。

## 已经做的

| 做法 | 效果（风车坡） |
|---|---|
| 关卡按 20 行切块：地形、墙、道具、草叶各自成块，离镜头 90 米以外的块不画（`LEVEL_CULL`） | 三角形从约 220 万降到 200 万以内；块太细（10 行）反而让 draw call 从 747 涨到 1154 |
| 远处浮岛按材质合并成 3 个网格 | 少 60 多个网格 |
| 离主角 72 米以外的敌人不画也不更新（`ENTITY_CULL`） | 少一百多个 draw call |
| 法线遍跳过 60 米以外的实例化道具块；阴影范围从 ±42 米缩到 ±34 米；栅栏不投影 | draw call 从 960 降到 855，三角形从 206 万降到 178 万 |

## 下一步

一帧的 draw call 大约是主遍 250、描边用的法线遍 370、阴影遍 340（风车坡，2026-11-02 实测）：

- 法线遍改成主遍多目标渲染（同时输出颜色和法线），省掉整整一遍，也省掉每帧遍历场景换材质的 CPU。要给所有在主遍里画的材质补第二个输出，不描边的物体用混合保住底下的法线，放到阶段 3 做
- 小兵的刚性零件按种类做实例化，同屏 20 个敌人从约 160 个 draw call 降到十几个
