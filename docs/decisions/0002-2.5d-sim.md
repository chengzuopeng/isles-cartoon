# ADR-0002 逻辑用 2.5D：格子加高度

- 状态：已采纳
- 日期：2026-10-31

## 背景

主仓库的逻辑是纯平面的：角色是圆，墙是格子，子弹是平面上的线段（`Bullet.pos` 是 `Vec2`），碰撞、寻路、视线都在格子上算。榴弹的高度只用来画抛物线，落点还是平面的。第一人称需要俯仰瞄准、高低差和跳，子弹要能打在矮墙上，也能从矮墙上面飞过去。

## 决策

- 关卡还是字符画格子，每格加地面高度和障碍顶面高度
- 角色是竖直圆柱，子弹带高度和俯仰；碰撞、视线、寻路照旧在格子上算，多一步高度判断
- 不引入物理引擎，不做导航网格
- 细节见[技术架构](../tech/architecture.md)「2.5D 世界模型」

## 考虑过的其他方案

| 方案 | 没选的原因 |
|---|---|
| 全 3D：Rapier 物理引擎做移动和射线检测，导航网格寻路，关卡在 Blender 里搭 | 能做多层地图和桥底下走人；但 sim 和关卡格式基本要重写，测试也要重来；Rapier 是新依赖，要先经用户同意。为一个还没定的试验不值得 |
| 纯平面，只把镜头放低 | 做不了俯仰瞄准和高低差，第一人称打起来像在走廊里平移 |

## 能做和不能做的

- 能做：坡、台阶、平台、半身掩体、高墙、跳上石头和草垛、站在高处往下打、榴弹按仰角落地、贴地扩散的冲击波
- 不能做：楼上楼下叠在一起的地方，比如两层的房子、桥底下走人、地道上面还有路

## 以后

试验通过、关卡确实需要多层结构时，再新开一篇 ADR 评估全 3D。
