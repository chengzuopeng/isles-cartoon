# ADR-0003 墨线渲染：WebGL 加自己写的屏幕空间描边

- 状态：已采纳，M0 量完性能后复核
- 日期：2026-10-31

## 背景

新画风要墨线勾边、两三档明暗、暗部网点、手绘天空和自发光泛光（目标图 `art/concept/style-frame-1-1.png`）。主仓库现在的受光材质是 `MeshStandardMaterial`，没有描边，也没有后处理。它的美术文档里写了「卡通着色加粗深色描边」，技术架构文档也写着已引入，但代码里一直没做。

## 决策

- 继续用 WebGLRenderer（three 0.186）
- 卡通材质：加载时把 `MeshStandardMaterial` 换成 `MeshToonMaterial`，用 `onBeforeCompile` 加暗部偏色、网点和硬高光
- 描边在屏幕空间做：按深度找外轮廓，按法线找内部转折。法线先用第二遍渲染（`overrideMaterial`），draw call 吃紧再换多目标渲染
- 后处理用 three 自带的 `EffectComposer`，几遍着色器自己写，不加新依赖
- 第一人称手臂单独渲染、单独描边，再合成上去
- 细节见[墨线渲染管线](../tech/rendering.md)

## 考虑过的其他方案

| 方案 | 没选的原因 |
|---|---|
| 只用外扩轮廓（复制一份网格、背面朝外推一圈） | 便宜，但画不出内部转折线；每个网格多一次 draw，敌人零件多，draw call 会翻倍。屏幕空间描边做好以后，角色可以再补外扩轮廓加粗 |
| WebGPURenderer 加 TSL 节点（后处理节点和多目标渲染都很方便） | 主仓库的渲染代码、着色器预热、贴图上传节流都是按 WebGL 写的，换渲染器等于连这些一起重写；WebGPU 在不同显卡上的表现也要重新摸。M0 如果发现 WebGL 下多目标渲染太别扭，再评估 |
| 第三方后处理库（比如 pmndrs 的 postprocessing） | 新依赖要先问用户；要的几遍着色器都很短，自己写更好控制 |
| 线条全部画进贴图 | 距离、角度一变线就不对；动起来的角色没法这样画 |

## 代价

- 法线遍让 draw call 翻倍，第一人称本来就看得多，要靠按区域剔除和实例化网格切块压下来
- 屏幕空间的网点在镜头移动时贴在屏幕上不动；M0 同时试一版贴在物体表面的
- 自己写的着色器要自己维护，three 升级时要回归一遍
